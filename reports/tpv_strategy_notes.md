# TPV 策略可程式化要点整理

来源：使用者提供网页 `https://www.qinglan.org/tpv` 与聊天截图。本文仅作为量化规则转译与回测设计依据，不构成投资建议。

## 一、网页公开规则摘要

青岚 TPV 将 TPV 定义为 **Three-Point Verify（三点验证）**，其核心不是传统的 Trend / Price / Volume 指标组合，而是以纯 K 线结构执行「找支点、画轨道、等验证」三步。公开页面强调以下规则：

| 模块 | 原文逻辑 | 可程式化方向 |
|---|---|---|
| T：Three | 两次成线，三次定势；只做第三次触点 | 用 swing high / swing low 识别趋势线，至少两点成线，第三次回踩/反抽时才允许触发。 |
| P：Point | 找具体、有逻辑支撑的支点/触点 | 入场必须接近趋势线、枢轴位、前高前低或波段结构位，避免远离支点追价。 |
| V：Verify | 刺破不算数，收线才有效 | 以 15m/1H 收盘价确认，而非盘中触碰；要求收线回到结构有效区。 |
| 风控 | 强制盈亏比 ≥ 2:1 | 仅保留第一目标 / 止损距离大于等于 2 的交易，或用 R 值过滤。 |
| 周期 | 4H 决定方向，1H 决定位点，小周期服从大周期 | 方向过滤仍保留 V3 的 4H + 1H 结构，15m 只做触发。 |
| 消息 | CPI、非农等大波动前通常观望 | 历史回测若没有经济日历，先以高波动时段或异常 ATR 作为代理过滤。 |

## 二、截图讯号结构摘要

使用者截图中的青岚 TPV 机器人讯号大致包含：方向、入场位、第一目标、第二目标、止损位、盈亏比、做单评分与做单理由。评分理由重复出现以下项目：

| 评分项 | 截图关键词 | 可程式化代理指标 |
|---|---|---|
| 趋势项 | 趋势项得 2–3 分、1H EMA55 向上/向下、15M 均线斜率支持 | 4H / 1H EMA55 斜率与价格位置、15m EMA 斜率同向。 |
| 位置项 P | 入场位接近斐波那契关键位、EMA55 压力位附近、挂单基于关键位 | 入场价距离 EMA55、前高/前低、Fib 0.382/0.5/0.618 或 pivot 距离不超过 ATR 阈值。 |
| 量能项 V | 买盘回流、抛压显现、反弹无力、抛压未完全显现 | 用 CVD 斜率、成交量相对均量、K 线实体/影线、收盘位置作为代理。 |
| 多周期一致 | 1H 与 4H 趋势不一致扣 1 分 | 若 4H 与 1H 方向冲突，则扣分或过滤。 |
| 风险调整 | 成交量比率缩量、震荡市风险、新闻过热扣 1 分 | 用 ATR 分位、波动状态、连续大实体、异常成交量作为风险扣分。 |
| 盈亏比 | 盈亏比 2.72、3.35、4.55 等 | 以目标距离 / 止损距离过滤，最低建议 2.0 或 2.5。 |

## 三、可转成 V4/TPV 回测的设计假设

现有 V3 已是「4H 定方向、1H 确认、15m 触发、多币种择优」。TPV 最适合不是替代 V3，而是作为 V3 的二次过滤与评分层。建议新增 **TPV score**：趋势一致、第三触点、关键位距离、收线验证、量能确认、R:R 与风险扣分。

初版改良优先目标应是提高胜率和 PF，而不是增加频率。若加入第三触点与收线确认，交易数大概率下降，但胜率可能上升。为了避免过拟合，至少同时观察胜率、PF、收益、最大回撤、交易数与平均持仓 R。
